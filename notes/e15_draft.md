# E15 (черновик) — Сессионный инференс SASRec без обучения: короткое окно + бленд

**Дата:** 2026-10-30 (ночь)
**Автор:** Elizaveta (+ Claude, эксперимент)
**Git commit:** e926f87+ (незакоммичено: scripts/e15_session_inference.py, results/e15_session_inference.json, results/e15_work/)

**Контекст**
E09 установил: сессионный скоринг поднимает классику в 2–3.3 раза — классические модели
скорили по всей истории и теряли next-item сигнал. SASRec (e128/len150/40эп) — лучший
генератор; фильтрованная сила на next1@9010 = 0.3190 (e10 control; monitor 0.2334 —
unfiltered, RePlay не фильтрует seen). Гипотеза E15 из плана E12–E17: то же усиление
можно получить на трансформере дёшево — на этапе инференса, блендом скоров одного
чекпойнта при полном окне (150) и коротком (последние 30/50 событий).

**Гипотеза**
(H15a) Rank-average скоров одного чекпойнта при полном и коротком окне подчеркнёт
локальный next-item сигнал (жанровые стрики, P=0.66) и даст +1–2% к фильтрованному
SASRec на next1@9010: полное окно усредняет стрики, короткое — сохраняет.
(H15b, опция) Второй проход с top-1 первого прохода в контексте (lookahead) —
покрытие gt-позиций 2–3.

**Изменение**
`scripts/e15_session_inference.py` (стадии check / inner / outer / last1 / lookahead).
Только инференс готовых чекпойнтов (inner/outer из `e05_sasrec_work/e07/e128_len150_ep40`,
last1 из `e10_hybrid_blend_work`), ничего не обучается. Короткое окно: sequences в
predict-parquet обрезаются до последних N событий (tail-slice), RePlay-ридер с левым
паддингом кладёт их в те же хвостовые позиции окна 150. Бленд: rank-norm на пользователя
(1 − (rank−1)/200) + среднее с весом w короткого окна; сетка short_len ∈ {30, 50} ×
w ∈ {0.3, 0.5, 0.7}. Протокол весов как в E10: подбор на inner (gt = первое событие
inner_valid, seen-фильтр по inner_train), фиксация, оценка на outer next1@9010.
Инварианты всех панелей: seen_in_top = 0, дубликатов нет, 6040 пользователей.

**Контроль / baseline**
Фильтрованный SASRec next1@9010 = 0.3190 (e10 control, воспроизведён бит-в-бит:
пул полного окна переиспользован из кэша e10, HR@10 совпал до 1e-6); unfiltered
monitor = 0.2334.

**Метрики** (recall@10 macro_relevant; в скобках unfiltered)

| Вариант | inner | outer (next1@9010) |
|---|---:|---:|
| соло окно 150 (контроль) | 0.3116 (0.2331) | **0.3190** (0.2334) |
| соло окно 30 | 0.3012 (0.2220) | 0.3010 (0.2233) |
| соло окно 50 | 0.3046 (0.2311) | 0.3109 (0.2293) |
| бленд 150+30, w=0.3 (лучший inner) | **0.3121** | 0.3180 |
| бленд 150+50, w=0.3 (потолок, подбор на outer) | 0.3098 | 0.3189 |

Полная сетка (outer): 30×{0.3/0.5/0.7} = 0.3180/0.3139/0.3094; 50×{0.3/0.5/0.7} =
0.3189/0.3169/0.3169 — монотонное убывание с ростом w, лучший всегда на минимальном w:
чем ближе к чистому полному окну, тем лучше.

**Результат**
- H15a: **rejected**. Честный (фиксированный inner-конфиг 150+30, w=0.3) бленд на
  outer = 0.3180 — **−0.31%** к фильтрованному SASRec 0.3190; даже диагностический
  потолок (лучший подбор на самом outer) = 0.3189 (−0.05%) не пробивает базу.
  Критерий «+1% → компонента E17» не достигнут.
- Диагностика причины (overlap): top-30 списков полного и короткого окон совпадают
  на 75% (окно 30) / 84% (окно 50); короткое окно вылавливает лишь 3.6% (30) / 2.2% (50)
  промахов полного окна. Комплементарности нет — короткое окно не новый сигнал,
  а зашумлённая версия того же.
- Побочный факт о ёмкости сигнала: соло короткое окно всего на 3–6% слабее полного
  (0.3010–0.3109 против 0.3190) — почти весь next-item сигнал SASRec извлекает из
  последних 30–50 событий, дальняя история почти не добавляет.
- last1-панель: **не посчитана** (todo) — на момент готовности outer CPU был занят
  параллельными e10/e11-прогонами, а чекпойнт e10 sasrec-last1 ещё дописывался
  тренером (best.ckpt mtime 02:55:15 > старта инференса 02:54:47 — окна использовали
  бы разные версии весов); прогон остановлен, отравленных кэшей нет. Догонка —
  `uv run python scripts/e15_session_inference.py --stage last1` (~10 мин) после
  завершения e10-трейна.
- H15b (lookahead): **отменён** (координация CPU при занятых 8 ядрах после
  отрицательного H15a); стадия реализована в скрипте и запускается `--stage lookahead`.

**Вывод**
- hypothesis rejected (H15a): урок E09 на трансформер не переносится. Классика
  выигрывала от ограничения окна, потому что скорила по всей истории равномерно;
  SASRec уже «сессионный» по архитектуре — attention локализует вес на последних
  позициях, и полное окно 150 не размывает короткие стрики, а использует вместе с ними.
- Для E17: сессионный скор E15 **не включается** в финальный бленд (критерий +1%
  не выполнен); short-window пулы не несут дополнительной информации к полному окну.
- Экономия для плана: инференсные «дешёвые» усиления на одном чекпойнте исчерпаны —
  прирост возможен только от других моделей (E14 seed-ансамбль: декорреляция через
  инициализацию, а не через окно) или ранкера (E11).
