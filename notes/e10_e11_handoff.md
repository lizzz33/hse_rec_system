**Overlap-диагностика комплементарности**
- 4113 пользователей с промахом SASRec в топ-10; markov+ease (4:1) ловят

- пересечение топ-30 SASRec и markov: Jaccard 0.29, |∩|/30 = 0.43 — пулы

**Результат и вывод**
Н10 отвергнута. Честный бленд 0.3179 не достигает планки 0.3254; даже
диагностический потолок с весами, подобранными на самой внешней оценке

пройдена тривиально — подтверждает её артефактную природу (смешение фильтров).
Причина провала — не подбор весов, а слабая комплементарность списков
(overlap 9.5%, пересечение пулов 0.43): markov/ease повторяют ядро топа
SASRec и добавляют шум на границе. Вывод: фиксированный rank-blend
классики с сильным SASRec не работает; сигнал markov/ease переносится
в гибрид только признаками ранкера (E11 — уже в прогоне).

### Фикс скрипта (единственный мой код-фикс E11, уже на диске)

`scripts/e11_hybrid_ranker.py`, `fit_ranker()`: после `model.fit(...)` мой
добавленный дамп важностей упал —

```
CatBoostError: Feature importance type EFstrType.LossFunctionChange
requires training dataset to be passed to this function.
```

Причина: для ранжирующих лоссов (YetiRank) CatBoost по умолчанию считает
важности типа LossFunctionChange, которому нужен датасет; безыдексный
`model.get_feature_importance()` работает только для PredictionValuesChange
(не поддерживается для ранжирования). Фикс: передать `train_pool` —
`model.get_feature_importance(train_pool)`.

Заодно (для отчёта/E17, минимальные добавления, стиль сохранён):
- `import json`;
- `fit_ranker(..., tag=...)` сохраняет модель `results/e11_ranker_work/catboost/{tag}.cbm`
  и важности `feature_importance_{tag}.json` (отсортированы по убыванию);
  теги вызовов: `inner_tail_full`, `inner_tail_e07`, `inner_next1_full`,
  `final_outer_tail` (сабмитный ранкер);
- payload `results/e11_hybrid_ranker.json` получает блок `feature_importance`
  по трём inner-ранкерам.

Репер: «ранкер обучен: N итераций» печатает best_iteration+1, а не общее
число итераций (N=46 в r2 — best-итерация, обучение шло полные 1500).
